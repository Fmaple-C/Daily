# 枫叶计划项目技术文档

## 技术目标

本项目当前目标是做一个本地离线、可持续迭代的 Android 计划应用。实现上优先保持依赖少、结构清楚、数据可迁移。

技术原则：

- 数据优先保存在本机。
- 第一阶段不引入第三方依赖。
- 业务规则、数据读写和界面代码分层。
- 每次数据结构升级必须有 `schemaVersion` 和迁移策略。
- 构建产物为 Android APK。

## 架构分层

### `MainActivity`

负责界面和用户交互。

主要职责：

- 构建今日聚焦首页、本周日期、日/月/年标签、周期完成进度、底部导航栏、圆形新建入口、主题切换入口、创建/编辑表单、轻量计划列表、底部操作面板、一言列表、随记列表和完整打卡历史页。
- 响应新建计划、编辑计划、选择日期、选择时间、打卡、新增一言、新增随记、编辑随记、删除等操作。
- 调用 `PlanRepository` 读取和保存数据。
- 调用 `PlanRules` 判断计划状态。
- 使用 `DateKeys` 生成日期和时间展示。

不负责：

- 直接读写 `SharedPreferences`。
- 直接解析或生成 JSON。
- 直接处理数据版本迁移。

### `model`

保存数据结构和常量。

- `PlanItem`：计划数据模型。
- `CheckIn`：单次打卡记录。
- `QuickNote`：一言记录模型。
- `MemoNote`：随记模型，保存 Markdown 原文和更新时间。
- `DailyData`：本地业务数据聚合模型，包含计划、一言记录和随记记录。
- `PlanConstants`：计划类型、周期模式常量。

### `data`

负责本地数据读写。

- `PlanRepository`：封装 `SharedPreferences`、JSON 解析、JSON 保存和旧数据迁移。
- `ThemePreferences`：保存日夜主题偏好。

### `domain`

负责业务规则。

- `PlanRules`：判断计划是否在当前日期生效、是否在当前周期已打卡、非生效状态文案。

### `util`

负责通用工具。

- `DateKeys`：生成 `yyyy-MM-dd`、`yyyy-MM`、`yyyy`、月初、月末、年初、年末、时间格式化和日期解析。

## 数据模型

### `PlanItem`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 计划唯一标识，当前使用创建时毫秒时间戳 |
| `type` | `String` | 计划类型：`daily`、`monthly` 或 `yearly` |
| `title` | `String` | 计划名称 |
| `note` | `String` | 备注，多行文本 |
| `scheduleMode` | `String` | 周期模式 |
| `startDate` | `String` | 开始日期，格式 `yyyy-MM-dd`，部分模式为空 |
| `endDate` | `String` | 结束日期，格式 `yyyy-MM-dd`，部分模式为空 |
| `deadlineMinutes` | `int` | 日计划截止时间，按当天 0 点起算的分钟数 |
| `createdAt` | `long` | 创建时间戳，单位毫秒 |
| `checkIns` | `List<CheckIn>` | 打卡记录 |

### `CheckIn`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 打卡记录唯一标识 |
| `targetType` | `String` | 打卡所属类型：`daily`、`monthly` 或 `yearly` |
| `targetKey` | `String` | 打卡周期键，日计划为 `yyyy-MM-dd`，月计划为 `yyyy-MM`，年计划为 `yyyy` |
| `checkedAt` | `String` | 打卡展示时间，例如 `2026-05-14 15:30` |
| `note` | `String` | 本次打卡备注 |
| `checkedAtMillis` | `long` | 打卡时间戳，单位毫秒 |

### `QuickNote`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 一言记录唯一标识 |
| `content` | `String` | 一言正文 |
| `createdAt` | `long` | 创建时间戳，单位毫秒 |
| `createdAtText` | `String` | 创建时间展示文本，例如 `2026-05-14 21:30` |

### `MemoNote`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 随记唯一标识 |
| `title` | `String` | 随记标题 |
| `content` | `String` | Markdown 原文 |
| `createdAt` | `long` | 创建时间戳，单位毫秒 |
| `updatedAt` | `long` | 最近更新时间戳，单位毫秒 |
| `createdAtText` | `String` | 创建时间展示文本 |
| `updatedAtText` | `String` | 更新时间展示文本 |

### `DailyData`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `plans` | `List<PlanItem>` | 所有计划 |
| `quickNotes` | `List<QuickNote>` | 所有一言记录 |
| `memoNotes` | `List<MemoNote>` | 所有随记记录 |

## 周期模式

| 常量 | 含义 |
| --- | --- |
| `daily_every` | 每日生效 |
| `daily_today` | 只在创建当日生效 |
| `monthly_every` | 每月生效 |
| `monthly_this` | 只在当前月份生效 |
| `yearly_every` | 每年生效 |
| `yearly_this` | 只在当前年份生效 |
| `range` | 指定开始日期到结束日期之间生效 |

## 数据迁移规则

### `schemaVersion = 1`

旧格式：

```json
{
  "schemaVersion": 1,
  "todos": []
}
```

迁移到当前版本：

- 每个旧 TODO 转为一个 `daily` 日计划。
- 周期模式设为 `daily_every`。
- 旧 `deadlineMinutes` 保留。
- 旧 `lastCompletedDate` 如果存在，会生成一条迁移打卡记录。
- 旧版本没有保存具体打卡时间，所以迁移记录使用 `当天 00:00`。
- 当前代码会保存为最新的 `schemaVersion = 5`。

### 旧版无版本数据

更早版本可能只保存 `todos` 数组。读取时会自动转为当前最新数据结构。

### `schemaVersion = 2`

旧格式已经包含 `plans` 和 `checkIns`，但 `CheckIn` 没有 `note` 字段。

迁移到 `schemaVersion = 3`：

- 读取旧打卡记录时，`note` 使用空字符串。
- 保存时继续迁移到当前最新结构。

### `schemaVersion = 3`

旧格式已经包含 `plans` 和带备注的 `checkIns`，但还没有 `quickNotes`。

迁移到 `schemaVersion = 4`：

- 读取旧计划和打卡记录。
- `quickNotes` 使用空列表。
- 保存时继续迁移到当前最新结构。

### `schemaVersion = 4`

旧格式已经包含 `plans` 和 `quickNotes`，但还没有 `memoNotes`。

迁移到 `schemaVersion = 5`：

- 读取旧计划、打卡记录和一言记录。
- `memoNotes` 使用空列表。
- 保存时写回 `schemaVersion = 5`。

### 后续规则

- 每次新增、删除或改变持久化字段，都要评估是否提升 `schemaVersion`。
- 新版本必须兼容旧版本数据。
- 迁移成功后应保存为最新结构。
- 不建议覆盖未知的更高版本数据，避免降级安装破坏未来数据。

## 主题方案

当前日夜主题由 `MainActivity` 内的调色板控制，用户选择由 `ThemePreferences` 保存。

当前规则：

- `false`：日间主题。
- `true`：夜间主题。
- 切换主题后重建当前界面。
- 主题偏好与计划数据分开保存，避免业务数据和 UI 偏好混在一起。

## 应用图标

应用图标使用 Android 原生资源：

- `ic_launcher_foreground.xml`：枫叶和对勾矢量前景。
- `mipmap-anydpi-v26/ic_launcher.xml`：adaptive icon。
- `mipmap-anydpi/ic_launcher.xml`：旧版本 fallback。

## 日期与状态逻辑

### 生效判断

`PlanRules.isActiveOnDate(plan, dateKey)` 负责判断计划是否在指定日期生效。

规则：

- `daily_every`、`monthly_every` 和 `yearly_every` 永远生效。
- `daily_today`、`monthly_this`、`yearly_this` 和 `range` 按 `startDate <= today <= endDate` 判断。

### 打卡判断

当前周期是否打卡由 `targetKey` 判断。

- 日计划当前周期键：`yyyy-MM-dd`。
- 月计划当前周期键：`yyyy-MM`。
- 年计划当前周期键：`yyyy`。

只要当前周期内存在至少一条打卡记录，就认为当前周期已打卡。

### 超时判断

当前只有日计划有超时状态。

规则：

```text
如果计划今天生效
并且今天没有打卡
并且当前分钟数 > deadlineMinutes
则显示已超时
```

## Markdown 展示

随记正文按 Markdown 原文保存，列表中使用 `MainActivity.markdownPreview` 做轻量展示。

当前支持：

- `#`、`##`、`###` 标题样式。
- `-`、`*` 和数字列表。
- `>` 引用。
- 缩进代码和 ``` 代码块提示。
- 去除行内 `**` 和反引号标记，让列表预览更干净。

当前不引入第三方 Markdown 解析库，主要原因是保持离线应用第一阶段依赖少、安装包小、迁移成本低。后续如果随记成为核心能力，可以接入成熟 Markdown 解析库或迁移到 Compose 富文本展示。

## 导航交互

主界面导航分两层：

- 计划类型标签：在计划模块内切换日计划、月计划、年计划。
- 底部导航栏：固定在页面底部，用于计划、一言、随记之间的高频切换。

日计划首页额外展示当前周的 7 天日期；日期仅作为时间上下文，当前版本不切换到历史日期。

动画实现：

- 点击计划项右侧省略号后，使用原生 `Dialog` 在底部展示操作面板，并执行透明度和纵向位移动画。
- 切换模块或计划类型后，列表使用短距离上移动画进入，减少页面突然切换的生硬感。

当前不引入动画依赖库，使用 Android 原生 `DecelerateInterpolator` 和 View Property Animator。

## 视觉设计基准

- 首页以日期和当前周期任务为第一视觉层级，不展示大尺寸功能选择区。
- 使用 4dp/8dp 间距节奏，页面左右边距为 20dp。
- 枫叶橙只用于新建、进度、当前标签和打卡主动作，不作为整页背景色。
- 计划列表使用分隔线而非独立厚重卡片；完成态使用低饱和绿色。
- 低频操作集中在原生底部 `Dialog` 面板，面板出现时使用遮罩和 200ms 上移动画。
- 高保真界面基准保存在 `design/daily-redesign.html`，用于后续界面迭代时保持布局一致。

## 构建方式

在项目根目录执行：

```powershell
.\gradlew.bat assembleDebug
```

生成 APK：

```text
app\build\outputs\apk\debug\Daily-版本-日期.apk
```

同时会保留一份到项目根目录的本地归档目录：

```text
release-apks\Daily-版本-日期.apk
```

当前构建命名规则由 `app/build.gradle` 自动控制：

```text
Daily-${versionName}-${yyyyMMdd}.apk
```

例如：

```text
Daily-0.9.0-20260801.apk
```

版本维护规则：

- 每次发布功能更新时，提升 `versionName`。
- 每次准备安装到已有手机应用上时，提升 `versionCode`，保持单调递增。
- 不手动重命名 APK，避免文件名和应用版本不一致。
- 构建新版时不执行清理旧包操作；通过新的 `versionName` 生成不同 APK 文件名，并将 APK 追加保留到 `release-apks`。

如果 Gradle 全局缓存损坏，可以尝试：

```powershell
.\gradlew.bat --stop
```

然后删除用户目录下的 Gradle 可再生缓存，例如：

```text
%USERPROFILE%\.gradle\caches\transforms-4
```

删除前需要确认路径确实位于 `.gradle\caches` 内。

## 当前限制

- `MainActivity` 仍然承担较多 UI 构建工作，后续可以继续拆成独立 UI 组件或迁移到 Compose。
- 当前完整打卡历史页按单个计划展示全部记录；后续可继续扩展为全局历史、筛选和搜索。
- 当前仍使用 `SharedPreferences`，大量历史数据后建议迁移到 SQLite 或 Room。
- 没有通知提醒。
- 没有自动化测试。
- 没有适配横屏、大屏和平板布局。

## 后续技术演进建议

### 阶段 1：继续整理 UI

- 把创建表单拆成 `PlanFormView`。
- 把计划卡片拆成 `PlanCardView`。
- 把顶部导航拆成 `PlanNavigationView`。
- 当前新建表单已默认收起，后续拆分 UI 时保留“列表优先”的布局原则。

### 阶段 2：补齐核心体验

- 增加全局打卡历史、筛选和搜索。
- 增加提醒通知。
- 增加数据导入导出。

### 阶段 3：升级存储

当打卡历史变多后，建议迁移到 SQLite 或 Room。

建议表结构：

- `plans`：保存计划基础信息。
- `check_ins`：保存每次打卡记录。
- `quick_notes`：保存一言记录。
- `memo_notes`：保存随记 Markdown 原文。

这样可以支持：

- 连续打卡天数。
- 月历视图。
- 每月完成率。
- 按计划查询历史。

### 阶段 4：测试

建议补充：

- `PlanRules` 单元测试。
- `DateKeys` 日期边界测试。
- `PlanRepository` 迁移测试。
- UI 冒烟测试。

重点测试边界：

- `00:00` 跨日。
- 刚好等于截止时间。
- 超过截止时间后补打卡。
- 日期范围开始和结束当天。
- 月计划跨月范围。
- 年计划跨年范围。
